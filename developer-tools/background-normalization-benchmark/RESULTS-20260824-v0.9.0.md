# v0.9.0 End-to-End Comparison: 2026-08-24

This comparison reruns `background_normalization_benchmark.py` on the same 220P
McNaught source, session split, cached Horizons ephemeris, and Siril WCS used by
the pre-v0.9 measurements. `time.perf_counter()` surrounds the complete pipeline
subprocess, so elapsed time includes registration, background processing,
stacking, cleanup, and normal output writing. Network ephemeris retrieval and
plate solving are excluded.

## Exact end-to-end results

| Version | Mode | Run | End-to-end | Stack-only timer | Workers |
| --- | --- | ---: | ---: | ---: | ---: |
| pre-v0.9 | `none` | initial | 828.093 s | unavailable | legacy |
| pre-v0.9 | `none` | later/warm | 579.404 s | unavailable | legacy |

| v0.9.0 | `none` | 1 | 219.510 s | 48.743 s | 4 |

| v0.9.0 | `quadratic` | 1 | 180.131 s | 75.987 s | 4 |
| v0.9.0 | `quadratic` | 2 | 182.808 s | 72.668 s | 4 |

The two v0.9.0 quadratic end-to-end runs average 181.470 seconds. Compared with
the pre-v0.9 quadratic result of 736.298 seconds, this is a 4.06x speedup and a
75.4% elapsed-time reduction over the same benchmark scope.

For `none`, the most defensible cache-matched comparison is the later pre-v0.9
run (579.404 seconds) against the second v0.9.0 run (136.979 seconds): 4.23x
faster and 76.4% shorter. Filesystem cache state is still a major variable, as
shown by the two v0.9.0 `none` runs.

The v0.9.0 stack-only timer is useful for profiling current operations, but the
old implementation did not record the same timer. It must not be divided into
the old end-to-end result. The earlier 8.7x to 10.0x claim mixed these scopes and
has been withdrawn.
